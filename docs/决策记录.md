# Android 决策记录

## 一、斜杠技能提示

决策日期：2026-10-15

1. 用户确认与 iOS 同期只完成 `/` 技能发现、筛选和点击补全；当时仅接技能；章节二扩展系统指令，章节三补充目录缓存；`@` 引用仍另行对接。
2. 使用公共插件的可选 v2 `skills` 能力，按当前会话读取主机目录；正文留给主机在发送后加载。缺少能力时继续普通输入。
3. 候选在输入框上方，名称有序子序列筛选且前缀优先。点选只替换光标所在的斜杠词，保留其余草稿和键盘，用户继续编辑后手动发送。组合输入、非空选区、完整路径和网址不触发候选。
4. 连接或主机变化、目录失效通知均丢弃旧目录和在途结果。协议模型与纯补全逻辑放在不依赖 Android 的 core 模块，输入框与键盘状态留在 app 模块。

## 二、系统指令

决策日期：2026-10-16

1. 用户选择完整系统指令方案：动态主机目录与执行、模型/文件原生入口、权限与确认、七类反馈、官方完整日志归档分享，与 iOS 语义保持一致。
2. 主机命令点选先补全，发送才执行；原生入口点选打开具体界面。按精确定义来源识别内置操作，显式选择的同名技能不会变为系统指令；未知指令不转发模型。失败保留草稿，网络不确定时先查看主机结果，不自动重试。
3. 附件先检查主机声明，文档是移动端提取正文，按文本文件上传；日志复用官方含子会话与附件的 ZIP，分块校验后分享。权限当前值从主机读取，完全访问与自动审查需确认。
4. 契约、全接口盘点和四类差异表以公共仓库《移动端命令对接说明》为准；真实主机与真机未完成业务验收，未发布。

## 三、目录内存与磁盘缓存

决策日期：2026-10-16

1. 用户选择方案二：技能、指令、模型目录同时增加内存和磁盘缓存；重启先显示旧列表再后台校验。模型当前选择和失败详情不落盘，权限与执行结果不缓存。
2. 内存五分钟有效，磁盘最长七天且恢复后必校验；手动刷新绕过有效期，同键请求合并。技能/指令变更与会话目录变化通知失效，模型当前选择由实时投影更新，重连重新验证；供应商目录没有专用通知时使用短有效期与手动刷新。
3. 按配对身份、主机、设备、TLS 指纹、会话和种类隔离；解除配对清理缓存。不兼容格式、损坏、键错误与异常时间重建，最多 64 份/16 MiB/单份 3 MiB，旧连接不能回填。
4. 原生权限/反馈入口先核对最新目录，权限执行附加期望定义标识；缓存只改善读取，不放宽操作确认。具体边界见公共仓库《移动端目录缓存》。

## 四、配对后引导

决策日期：2026-10-17

1. **范围与形态**：与 iOS 同步，配对成功后一次性展示 4 页全屏横向分页：已连接电脑、实时会话与流式输出、审批与提问、通知。视觉沿用 iOS 设计稿（`Theme.kt` 已照搬 iOS 的 token），图标换用 Material Icons。iOS 一侧的取舍见 iOS 仓库《决策记录》第八章。
2. **存量用户不打扰**（选 A）：升级前就已配对的用户，首次对账时直接记为已完成，不展示引导。被否决的方案：也展示一次；只在通知未决定时展示末页。
3. **保留「稍后再说」**（选 A）：选择后不申请通知权限，也不再自动追问；之后在设置页「通知」里补开。被否决的方案：去掉按钮、保持「必须申请」。
4. **完成后进入工作台**（选 A）：显示「一切就绪」约 1.2 秒后自动淡出。设置页「关于」末行增设「重看引导」；重看模式不记录完成状态、不申请任何权限，末页主按钮为「完成」、没有「稍后再说」，走完直接关闭。
5. **末页按通知状态分支**（选 A）：未决定显示「开启通知」加「稍后再说」；已授权显示「完成」，不再弹窗；已拒绝显示「前往系统通知设置」加「稍后再说」，并改写说明文案。
6. **第 4 页如何讲 Android 的通知**（选 A）：Android 没有远程推送，通知靠前台服务「保持连接」（默认开启）发出，所以不沿用 iOS 的「推送通知」说法。仍是 4 页，不加第 5 页；说明改为「保持连接」开启时的本地通知，末页提示该开关默认开启。被否决的方案：加第 5 页讲后台保持连接与电池白名单；照搬 iOS 文案。
7. **系统返回键**（选 A）：引导中非首页回到上一页，首页按系统默认退出 App；预测性返回同理。被否决的方案：一律视为「跳过」。
8. **通知三态规则**：由 `NotifyState.from(canPost, permissionRequired, permissionGranted, asked)` 归并。`canPost`（已授权且系统里没关通知）为真是已授权；否则，设备需要运行时授权（API 33+）、权限未授予且应用还没弹过授权框，是未决定；其余情况是已拒绝，包括 API 32 及以下用户在系统里关了通知、拒绝过授权框、权限已授予但通知被关。已拒绝时授权框帮不上忙（系统可能不再弹出），按钮只引导去系统通知设置。「是否弹过授权框」由 `onboarding.notificationAsked` 记录。
9. **通知授权的申请时机**：原先 `MainActivity.onPaired()` 在配对完成后立即申请，并且每次冷启动只要已配对、尚未授权就会再申请；改为待引导的用户由引导末页触发，`onPaired()` 不再抢先申请。前台服务照常启动，连接不受影响。
10. **完成标记**：按设备记录，不按主机记录，增加第二台主机不会重复引导。SharedPreferences 键为 `onboarding.completedVersion`、`onboarding.armedVersion`、`onboarding.notificationAsked`。首次对账时已配对记为已完成，未配对记为「待引导」，配对成功后展示一次；完成后解除配对再重配也不再展示；中途退出则下次冷启动再次展示。版本号升级只对尚未配对的新用户生效，不让已配对用户重新看到引导。
11. **代码落点与平台信号**：纯逻辑（`OnboardingState`、`OnboardingFlow`、`NotifyState`、`OnboardingMotion`）放 `core` 的 `onboarding` 包并配 JUnit 测试，界面放 `app`；时间轴常量与 iOS 一一对应。「减弱动态效果」取系统动画缩放为 0（Android 的「移除动画」就是把它设成 0），此时直接取终态、按钮翻页直接切换；`fontScale` 达到 1.5 及以上时隐藏舞台，只留标题与正文。
12. **构建口径**：机器默认的 JDK 25 超出 Gradle 8.14.3 的支持范围，构建改用 `~/.gradle/jdks` 里的 JDK 21，通过 `JAVA_HOME` 指定，不改项目配置。改动前基线为 `:core:test` 70 项与 `:app:assembleDebug` 通过。本仓库不是 git 仓库，没有历史可回退，改动前另留了源码快照，不放进项目目录。
13. **分期与验证口径**：阶段 0（快照与基线）、阶段 1（`core` 逻辑与 36 项新测试，`core` 共 106 项通过）、阶段 2（`OnboardingPrefs`、`MainActivity` 门禁、`AppRoot` 叠加层、`OnboardingScreen` 与 4 页静态舞台、中英文案、调试预览入口 `OnboardingPreviewActivity`）、阶段 3（入场动效：`withFrameNanos` 时间轴、线稿用 `PathMeasure` 描边）、阶段 4（设置页「关于」末行「重看引导」与 `MainShell` 重看路由、TalkBack 语义、返回键、深色 / 大字号 / 宽屏复核）已完成（2026-10-17）；阶段 5（新增《配对后引导验收》、README 补一行、全量构建）已完成（2026-10-17）。入场动效的原则与 iOS 相同：静止态即终态，页面离开不闪回起点；系统动画缩放为 0 时直接取终态、按钮翻页直接切换，第 3 页例外，静止展示待审批半屏；播完即停止刷新，只有第 1 页虚线流动与第 2 页光标闪烁在页面可见期间继续。通知授权弹窗的时机、前台服务保活、国行机电池白名单、TalkBack 实际朗读、动效流畅度只能真机验收，模拟器结果不写成已验收；模拟器是 API 37，只能覆盖 Android 13 及以上的授权分支，API 32 及以下靠 `NotifyState` 的单元测试。设置页入口只做了编译与逻辑审阅：模拟器上没有已配对主机，无法实际点进去，重看路由走的是同一个 `OnboardingScreen` 的 `Replay` 模式（已在调试预览里验证末页为「完成」、无「稍后再说」）。
14. **主按钮高度改为最小高度**：共用的 `ProminentButton` 把固定高度改成最小高度并加上下 8dp 内边距、文字居中。原因：字体放到 2.0 倍时末页「前往系统通知设置」折成两行，固定高度会把主操作裁掉；正常字号下标签比最小高度矮，高度与改动前完全一致。所有用到该按钮的页面都受益，但没有逐页回归，已在验收文档里列为需要抽查的项。
