# 技能提示验收

## 一、实现与契约

1. 请求 `c2s.session.skills`，响应 `s2c.session.skills`；可选能力为 `skills`，缺省 false。`s2c.skills.changed` 只表示目录失效，当前打开的候选重新读取。
2. 目录内容为名称、说明、模型调用标记。`modelInvocable=false` 仍可用户调用，显示「仅限用户调用」。不在手机扫描技能文件，不传送正文。
3. 逻辑按桥接主机、连接代次和会话隔离。协议权威文档位于公共 `dsh-deeppilot` 仓库，完整差异与上游文档清单见其中 `docs/技能提示对接说明.md`。

## 二、本地验证

1. 2026-10-15 已通过 57 个核心测试与调试包构建。使用已有 JDK 21 执行 `./gradlew :core:test :app:assembleDebug`；默认 JDK 25 与当前构建工具不兼容，不能据此判定源码失败。
2. 回归覆盖 Unicode 文字中间的光标替换、筛选排序、路径与组合输入排除、旧桥接能力缺省和仅用户调用技能解码。
3. `SkillCompletionActivity` 只在调试构建中存在，使用六条合成技能、多段长描述与真实产品输入器。紧凑布局在模拟器深浅色下均验证了末项滚动、筛选回首项、单行说明和面板收缩；点选 `/review` 后继续输入得到 `/review check`，发送计数为 0，系统键盘仍显示。
4. 紧凑展示：技能名称与说明各最多一行，长说明尾部省略，换行合并；仅用户调用标记并入说明行。少量候选随内容收缩，普通字号最多三条，更多在内部滚动；保留完整文本供无障碍读取。
5. 真实主机技能正文加载、不同厂商真机输入法和无障碍朗读仍需真机验收；离线入口不能替代这些证据。
